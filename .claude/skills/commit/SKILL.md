# 建立符合規範的 Commit

## 步驟

1. 執行 `git status` 與 `git diff`（含 `git diff --staged`）了解變更內容。
2. 若變更包含多種不相關的類型，先向使用者提議拆成多個 commit。
3. 依下表選出**最貼切的一個** gitmoji。
4. 撰寫訊息（格式見下方），用 `git add` 加入相關檔案後 commit。
   - 不要加入 `.env`、金鑰等敏感檔案。
   - 不要使用 `--no-verify` 跳過 hook；hook 失敗時修正問題後建立新的 commit。
5. 執行 `git status` 確認 commit 成功。
6. 本專案允許自動 push：直接 `git push`（無 upstream 時用 `git push -u origin <分支>`）。沒有 remote 時略過並告知使用者；禁止 force push。

## 訊息格式

```
<gitmoji> <標題：繁體中文、動詞開頭、≤ 50 字元、句尾無句號>

<內文（選填）：說明為什麼要改、重要細節，可條列>
```

- 使用 Unicode emoji（`✨`），不要用 shortcode（`:sparkles:`）。
- 程式碼識別字、套件名、檔名等保留原文，可用反引號包住。
- 多行訊息在 PowerShell 用 here-string `@'...'@`，在 Bash 用 heredoc。

## 範例

```
✨ 新增動畫追蹤清單匯出功能

- 支援匯出為 CSV 與 JSON
- 匯出時保留觀看進度與評分
```

```
🐛 修正登入後 cookie 未正確儲存的問題
```

```
⬆️ 升級 `requests` 至 2.32.3
```
