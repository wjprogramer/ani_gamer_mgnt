Netflix 支援調查

調查日期：2026-10-26・方式：在登入狀態下檢查頁面 DOM 與網路請求（未播放影片，以免新增觀看紀錄）。網站改版後需重新驗證。

結論：可行，但觀看紀錄比動畫瘋粗。Netflix 的觀影動態只有日期、沒有時間與進度，所以同步回來的紀錄只能精確到「哪一天看了哪一集」。在這台電腦上播放時，仍可像動畫瘋一樣精確記錄時間與進度。資料表原本就以 source + external_id 設計，不需要改結構。

1. ID

ID意義出現位置
作品 ID影集或電影，對應 anime_source.external_id卡片連結 /browse?jbv=<id>、/title/<id>
影片 ID單集（電影則與作品相同），對應 episode.external_id觀影動態的 /title/<id>、播放頁 /watch/<id>

觀影動態只給單集的影片 ID，不給作品 ID；要知道屬於哪部作品，需另外查詢（見第 5 節）。

2. 卡片（首頁、類別頁）

資料來源
卡片a[data-uia="standard-card"]、排行榜 a[data-uia="ranked-card"]
作品 ID連結的 jbv 參數
名稱連結的 aria-label
圖片卡片內 img，網址在 *.nflxso.net

class 名稱是編譯產生的雜湊值（例如 default-ltr-…-cache-16qxjbe），不能當選擇器；data-uia 比較穩定。列表是虛擬捲動，捲動時會重建節點，要用 MutationObserver 持續處理。

3. 觀影動態 /viewingactivity

資料來源
每一列li.retableRow[data-uia="activity-row"]，由新到舊
日期.col.date，格式為「YY/M/D」，沒有時間（格式可能隨帳號語系不同）
名稱與影片 ID.col.title a：連結 /title/<影片 ID>；文字為「作品：第 N 季：集名」，電影只有名稱
更多紀錄「顯示更多」按鈕，每次多載入 50 筆
APIPOST /api/aui/pathEvaluator/web/^2.0.0?method=call&callPath=["aui","viewingActivity",頁,筆數]（falcor）。需要帶頁面上的授權參數
其他有「全部下載」可匯出 CSV（同樣只有名稱與日期）；每個設定檔的紀錄分開

觀察到的 70 筆中，同一集沒有重複出現，推測與動畫瘋一樣每集只留最近一次的日期，重看會覆蓋。待驗證：重看已看過的一集後，舊的那筆是否消失。

4. 播放頁 /watch/<影片 ID>

未實地確認（避免新增觀看紀錄）。實作前需要使用者播放一集後再調查：

  • 影片 ID 在網址上；換集時網址會變，但不一定重新載入頁面（同動畫瘋的處理方式）。
  • 頁面上有 <video>，可沿用現有的 trackWatch（播放、暫停、進度回報）。
  • 作品 ID、名稱、集數需要從播放器的標題區或頁面資料取得，選擇器待確認。

5. 與現有架構的差異

項目動畫瘋Netflix
同步的時間精確度秒日期
同步的進度最近一集有沒有
觀看紀錄 → 作品直接帶 animeSn只有影片 ID，要另外查作品 ID；或先用名稱「作品：…」分組
同步方式公開的 JSON APIfalcor API 需授權參數；較簡單的做法是在觀影動態頁讀 DOM

封面固定網址CDN 網址可能會失效，要在取得時就下載
範圍都是動畫有各種影片，需決定只處理動畫還是全部
