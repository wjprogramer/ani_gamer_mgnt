動畫瘋個人管理工具：可行性評估

狀態：M0–M7 已實作・建立日期：2026-10-23・最後更新：2026-10-26（實作時的調整見第 5 節「實作時的調整」）

結論：四項需求都可行。架構採 Chrome Extension + 本機 Server：資料一開始就以實體檔案（SQLite + 封面圖檔）存在硬碟上；server 沒開時，extension 要主動提醒。 實作前唯一需要先驗證的是：首頁卡片是否只帶單集 sn（隱藏功能需要對應回動畫 sn）。

1. 需求摘要

  1. 隱藏動畫：在首頁、所有動畫列表等頁面的動畫卡片上加上「隱藏」按鈕。
  2. 評論：針對動畫撰寫評論，儲存在本機。
  3. 本機資料庫：記錄自有 ID、動畫瘋 ID、動畫名稱、封面（存到本機）；偵測到播放時自動記錄觀看日期時間。
  4. 觀看狀態標示：在卡片上標示「看到第 N 集」或「已看完」。

2. 決策紀錄

4. 各需求分析

4.1 隱藏動畫

  • Content script 注入 ani.gamer.com.tw，用 MutationObserver 偵測動畫卡片（包含延遲載入的部分），在卡片上插入按鈕，並依隱藏清單處理卡片。
  • 識別方式：animeRef.php?sn= 是動畫（作品），animeVideo.php?sn= 是單集。隱藏以動畫為單位；遇到只連到單集的卡片，查詢「單集 sn → 動畫 sn」對應快取，查不到時由 server 或 background 抓一次單集頁面來解析，並記錄結果。
  • 涵蓋頁面：首頁、所有動畫列表優先，之後再擴充到搜尋結果、排行榜、季番表、播放頁推薦區。用「頁面 → 卡片選擇器」設定表管理。
  • 呈現方式：預設摺疊成一行「已隱藏：XXX（還原）」，另提供「暫時顯示全部」的開關，以及隱藏清單的管理頁。
  • 續作不連動，每個動畫 sn 各自獨立隱藏。

4.2 評論

  • 在動畫頁和播放頁上注入評論面板（也可以考慮做成 extension 的 side panel），管理頁也能編輯。
  • 欄位：評分（選填）、內文、是否含劇透、建立與更新時間；保留 episode_id，之後可擴充單集評論。

4.3 動畫資料、封面與觀看紀錄

  • 建檔：第一次瀏覽某部動畫的動畫頁或播放頁時，解析名稱、封面網址和 sn，送到 server 建檔。
  • 封面：由 extension background 下載（有 host_permissions 就不受 CORS 限制）後上傳給 server，server 存成 data/covers/<anime_id>.jpg。也可以改由 server 直接下載。
  • 播放偵測：播放頁的 <video> 第一次觸發 playing 時，記錄一筆觀看紀錄（時間、單集、動畫），之後定期回報進度與片長，用來判斷是否看完和顯示觀看狀態。
  • 匯入既有紀錄（可選）：在管理頁提供「匯入動畫瘋觀看紀錄」按鈕，由使用者手動觸發，解析觀看紀錄頁後寫入；這類紀錄標記為 source = 'import'。

4.4 觀看狀態標示

  • 和隱藏功能共用卡片偵測。依觀看紀錄在卡片上加上標章，例如「看到第 5 集」或「✓ 看完」。
  • 「看完」的判定：最新一集的進度達到片長的 85%（數值可在設定中調整）。

Server 沒啟動時的處理

  • Background 定期呼叫 GET /api/health（也會在進入動畫瘋頁面時呼叫）。
  • 呼叫失敗時：extension 圖示的 badge 顯示紅色「!」，並在動畫瘋頁面上跳出提示「本機 server 未啟動，觀看紀錄暫存中」。
  • 建議：在 chrome.storage.local 暫存還沒送出的事件（觀看紀錄、隱藏、評論），server 恢復後自動補送，避免資料遺漏。
  • 選做：提供腳本，把 server 註冊成 Windows 登入時自動啟動（工作排程器或 pm2）。

注意事項

  • Content script 不直接呼叫 localhost（會受頁面 CORS 與 Private Network Access 限制），一律透過 background 轉送。
  • 本機 server 的安全性：只綁定 127.0.0.1；檢查 Host（防 DNS rebinding）並只允許 extension 與管理頁的 Origin，防止其他網站在背景呼叫你的 localhost。
  • MV3 的 service worker 隨時會被關閉，狀態不能只放在記憶體裡。
  • data/ 不進 git（加到 .gitignore），路徑可以設定；備份時直接複製整個資料夾。

6. 資料模型草案

核心原則：自有 ID 與來源 ID 分開，一部動畫可以對應多個來源。

anime            id (ULID), title, alt_titles (JSON), cover_path, hidden, hidden_at,
                 hidden_reason, created_at, updated_at
anime_source     anime_id, source ('bahamut'), external_id (animeRef sn),
                 url, raw_meta (JSON), first_seen_at
episode          id, anime_id, source, external_id (animeVideo sn), label ('第 3 集'),
                 sort_order
watch_event      id, episode_id, anime_id, started_at, last_seen_at,
                 progress_sec, duration_sec, completed, source ('auto' | 'import')
review           id, anime_id, episode_id?, rating?, content, spoiler,
                 created_at, updated_at
sn_cache         source, episode_sn, anime_sn, fetched_at
  • ID 用 ULID（可依時間排序）；時間一律以 UTC 的 ISO 8601 格式儲存，顯示時再轉成本地時間。
  • alt_titles 用來存日文原名或英文名，方便未來和其他網站比對同一部動畫。

8. 其他注意事項

  • 網站改版：選擇器集中放在一個檔案裡；抓不到元素時用 badge 提示，不要默默失效。可以存幾份實際頁面的 HTML 當成測試資料。
  • 請求頻率：背景抓單集頁和封面時要節流並快取。
  • 著作權：封面只供個人本機使用、不對外散佈。
  • Schema 遷移：從第一版就以 PRAGMA user_version 管理遷移（apps/server/src/db.ts）。

9. 里程碑

  1. ✅ M0 調查：實際擷取首頁、所有動畫、動畫頁、播放頁、觀看紀錄頁的 DOM，確認選擇器與 sn 的取得方式。
  2. ✅ M1 基礎：建立 monorepo；server（SQLite、健康檢查、Host／Origin 檢查）；extension 骨架（background 代理、server 狀態提醒、暫存佇列）。
  3. ✅ M2 建檔與觀看紀錄：自動建立動畫資料、下載封面、偵測播放並記錄。
  4. ✅ M3 隱藏與觀看狀態：卡片按鈕、sn 對應快取、標章、隱藏清單管理。
  5. ✅ M4 評論與管理頁：評論面板；管理頁可瀏覽動畫、觀看紀錄、評論與隱藏清單。
  6. ✅ M5 可選匯入：在觀看紀錄頁加上匯入按鈕，由使用者自行決定是否匯入。
  7. ✅ M6 觀看紀錄同步：背景每 6 小時、以及開啟觀看紀錄頁時，同步動畫瘋的觀看紀錄（含其他裝置看的）。動畫瘋上同一集重看會覆蓋舊時間，本機則保留每一次。
  8. ✅ M7 Netflix 與合併：Netflix 卡片、播放記錄、觀影動態頁同步；管理頁的合併頁列出疑似同一部的作品。

M6 的重複判斷

動畫瘋的觀看紀錄沒有每筆的 id，每集只留最近一次的時間（例如依序看 1、2、3 集再重看第 1 集，動畫瘋只剩 1、3、2）。因此以「同一集＋開始時間」判斷：

比對對象視為同一次的範圍處理
之前同步過的紀錄觀看時段（開始～最後回報）前後 2 分鐘內重疊（容許舊版以頁面匯入的分鐘誤差，以及 Netflix 推算開始時間的誤差）進度有增加就更新，否則略過
本機播放時的自動記錄觀看時段前後 30 分鐘內重疊（兩邊的時間來源不同）略過，以自動記錄為準
都不符合—新增，所以重看會保留成 1、3、2、1 共四筆

限制：只有同步時還留在動畫瘋上的紀錄才收得到。兩次同步之間在其他裝置重看同一集兩次，較早那次會被動畫瘋覆蓋；保存期限約 1 年。除了最近看的那一集，其他集沒有進度。
